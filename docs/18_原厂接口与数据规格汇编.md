### ⚠️ 鉴权的普遍真相

**14 份文档中没有任何一处描述签名算法 / token / AK-SK / 时间戳+nonce。** 实际鉴权只有三种：

| 方式 | 用于 |
|---|---|
| **IP 白名单报备**（未报备 → `403 Forbidden!`） | 平台数据对外接口、获取通话记录、技能组查询、黑红名单 |
| `Account` + `PBX`（由接口提供方发放） | 保持/恢复、挂机、查询坐席状态、签入签出、Webcall |
| `AccountId` + `AccountPass`（管理员登录用户中心密码） | 仅技能组信息查询接口 |

且明确要求：**只允许从第三方服务端发起，禁止浏览器直接调用**。

## A.1 事件推送接口 ★

| 项 | 原文 |
|---|---|
| 传输 | **GET**，参数在 URL query 中；**参数名固定，必须用平台定义的名字** |
| 自定义参数 | 可通过增加**弹屏变量**追加客户自定义参数，用于传递唯一标示 |
| 接收成功 | 第三方**必须返回字符串 `200`** |
| 失败判定 | 返回值不是字符串 `200` 即失败 |
| 重发策略 | **需单独申请开启，默认关闭**；10s → 30s → 60s → 600s 后重发，**4 次全败则停止** |

## A.2 Webcall 接口 2.6（外呼）

**GET** `http://<pbx>/command?Action=Webcall&...`

| 参数 | 必填 | 说明（原文） |
|---|---|---|
| `Action` | 是 | Webcall（固定） |
| `PBX` | 是 | 账号所在 pbx 的 ID |
| `Account` | 是 | 账户 ID |
| `ServiceNo` | 是 | 想要被叫进入的服务号码 |
| `Exten` | 是 | 被叫电话号码 |
| `WebCallType` | 否 | 传 `asynchronous` 采用异步接口（不填为同步） |
| `CallBackUrl` | 异步必传 | 回调地址，**仅支持 http** |
| `CallBackType` | 否 | get / post（默认 get） |
| `Variable` | 否 | `var1:value1,var2:value2`；**可携带 `CdrVar`，会在通话事件推送中传给第三方** |
| `ActionID` | 否 | 唯一标示，response 返回此字段 |
| `Timeout` | 否 | **20~60 秒**，默认 20 秒，含振铃时间 |
| `MaxCallTime` | 否 | 双向回呼场景的最大通话时长（秒） |
| `ChatingIvrPrompt` | 否 | 双向回呼中给双方播放提示 IVR，格式 `秒-服务号-变量;秒-服务号-变量`，多次提醒用**英文分号**分隔，多变量用**英文逗号** |

**同步响应**：被叫响应后才返回（超时 20 秒）。
```json
{"Command":"Response","Succeed":true,"Message":"4","ActionID":"Webcall1382293010856915711","Response":"Webcall"}
```

**`Message` 取值**：

| 值 | 含义 |
|---|---|
| `4` | 被叫已接听 |
| `0` | 被叫号码无效 |
| `3` | 被叫拒接/振铃未接/占线/关机/空号 |
| `8` | 线路繁忙/异常 |

**异步**：立即返回 → 呼叫被叫 → 被叫响应后向 `CallBackUrl` 推送 `?actionid=xxx&Message=4`。

**真实示例（60 秒通话，30s 与 50s 各提醒一次）**：
```
MaxCallTime=60&ChatingIvrPrompt=30-01056332288-notice:30;50-01056332288
```

## A.3 保持 / 恢复 / 挂机（同一套协议）

**GET** `http://<节点>/app?Action=<Hold|Unhold|Hangup>&...`

| 参数 | 必填 | 说明 |
|---|---|---|
| `Action` | 是 | `Hold` / `Unhold` / `Hangup` |
| `ActionID` | 是 | **最大 40 字节** |
| `Account` | 是 | 账户编号，如 `N0000000012` |
| `CallID` | 二选一 | 由通话事件推送获取（**都传以 CallID 为优先**） |
| `Agent` | 二选一 | 座席号 8000/8001/8002 |
| `PBX` | 是 | 账户所在 PBX |

**响应**：
```json
{"Response":"Hangup","ActionID":"34534jh9i23","Succeed":false,"Message":" Null channel!"}
```

**Message 错误含义**：

| 原文 | 含义 |
|---|---|
| `Null channel! or Null CallID！or Null Agent！` | CallID 有误 / 通话已不存在 / 未传座席号 |
| `Null channel!` | 要操作的通话已不存在 |
| `Channel is not linked!` | 通话已断开 |
| `Call not found!` | 通话未找到 |
| `Account or Agent no Channel!` | Account 和 Agent 有误 |
| `Invalid PBX!` | PBX 字段有误 |

## A.4 查询坐席状态 / 签入 / 签出（同一套协议）

**GET** `http://<ip>/app?Action=QueryExtenState|SignIn|SignOut&...`

| 参数 | 说明 |
|---|---|
| `Action` | `QueryExtenState` / `SignIn` / `SignOut` |
| `ActionID` | 最大 40 字节 |
| `Account` / `Exten` / `PBX` | 同 A.3 |
| `ExtenType` | **仅签入**：非必传，**不传签入手机，传的话值只能为 `gateway`** |

**响应**：
```json
{"Command":"Response","Succeed":true,"Flag":"signout","Message":" 小休 ",
 "ActionID":"queryExtenState0.41748595997291212","Response":"QueryExtenState"}
```

### ★ Flag 状态枚举（与 12 篇的 CTI 数字枚举完全对应）

| Flag | 含义 |
|---|---|
| `signout` | 签出 |
| `Reserve` | 离线接听 |
| `0` | 空闲 |
| `1` | 忙碌 |
| `2` | 小休 |
| `99` | **正在通话** |
| `3-9` | 自定义状态 |

> 这解释了 15 篇记录的"CTI 状态 0~15 + 99"——**服务端实际只定义 0/1/2/99 + 3~9 自定义**，其余为前端扩展。

**签出约束**：坐席必须处于**离线接听状态**才能签出，否则返回 `Reason=301`。
**签入错误**：`User has not bind gateway sip number or gateway sip number not register!`（未注册或未绑定 sip 号）。
