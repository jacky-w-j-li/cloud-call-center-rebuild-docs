## 三、请求链路（最关键的一张图）

```
浏览器(ExtJS)
   │ ① POST /action   { action:"xxx", data:"{...}" }
   ▼
nginx(80) ──proxy_pass──▶ cc-server-in(Node 3000)
                             │ ② 鉴权(session/token) + 校验
                             │ ③ 直接读写 Mongo(cc)  —— 多数业务在这层就结束
                             │ ④ 需要话务/复杂逻辑：用同一套 action 协议转发
                             ▼
                       cc-java-in(Java 9999) ──▶ Mongo(cc / report)
                             │ ⑤ 需要改 IVR / 分机 / 服务号
                             ▼
                       ass(AGI 7891) ──▶ 写 /etc/asterisk/**/*.ael,*.conf ──▶ reload

坐席话机 ──SIP──▶ Asterisk(6060) ──AGI agi://127.0.0.1:7891/xxx──▶ ass ──▶ Mongo
                       │
                       └── CDR ──▶ cccdr(8083) ──▶ Mongo(report 库)
```

三条要点：
1. **Web 层不直接操作 Asterisk**，全部经由 `ass` 这个自研 AGI 服务（OSGi 插件式，40+ bundle）。
2. **Asterisk 只在建链阶段同步调用 AGI**；通话一旦建立，SIP 状态机与 RTP 全在 Asterisk 进程内自包含 —— 这是"业务服务挂了电话不断"的根本原因。
3. **页面改 IVR 会写回 `.ael` 文件再 reload** —— 容器化时最大约束：`/etc/asterisk` 必须是**可读写共享存储（RWX）**，不能放 ConfigMap。

## 五、可用性分层（重建前必须理解）

| 级别 | 组件 | 崩了会怎样 |
|---|---|---|
| **L0（崩了不影响已建通话）** | cc-server-in / cc-java-in / socket-push / yy-server / bill / report / ES / Solr / Mongo / Redis / MySQL | 正在通话的电话**不断**；但新呼入路由、弹屏、IVR 变更会失败 |
| **L2（崩即断）** | **Asterisk 实例本身 + gateway + ass(AGI)** | 建链阶段就断，已建立的通话也会断 |

其它实测结论：
- **假冗余**：159 的 `.1`~`.9` 九个实例 `accounts/` 目录**全空**（仅未注册测试号），488/489/490/491 四个租户全挤在 `.0` → 一个实例挂 = 全租户断。
- **自愈≈0**：`asteriskGuard` 只监控不重启；`ass_monitor.sh` 的 cron 全被注释（日志停更于 2023-06-13）；**156 完全无开机自启**；只有 159 有完整 rc.local。
- **计划内中断**：每天 04:00 `gateway_restart.sh` 硬重启 gateway。
- **数据零复制**：Mongo 非副本集；Redis `connected_slaves:0`。
- **⚠️ RTP 端口只有 6 个**：`rtp.conf` 里 `rtpstart=10000 / rtpend=10005` → 并发上限约 **3 路**。这是当前系统最硬的功能性瓶颈之一。
