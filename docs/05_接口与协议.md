## 一、核心协议：自研 RPC（`action` 协议）

**这不是 REST。** 整套系统（浏览器 ↔ Node ↔ Java）跑的是同一套私有 RPC。

### 1.1 请求

```
POST /action  HTTP/1.1
Content-Type: application/x-www-form-urlencoded

action=customer.queryCustList&data={"page":1,"size":20,...}&_aid=12345
```

- `action`：**点分命名** `<命名空间>.<方法名>`，如 `customer.queryCustList`、`notice.createNotice`。
- `data`：JSON 字符串（业务参数）。
- `_aid`：请求 ID，用于链路日志（`perform-analysis[_aid]`）。
- 鉴权：session/token（`sessionTimeoutMinutes: 480`）。

### 1.2 分发实现（Node 侧）

```js
var actions = {            // 52 个命名空间，共 712 个 action
    oem:       { getOemInfo: oemHandler.getOemInfo, … },
    customer:  { queryCustList: app_customer_handler.queryCustList,
                 queryCustActions: …, updateCustomer: …, mergeCustomer: … },
    business:  { … }, batch: { … }, task: { … }, report: { … },
    callSheet: { … }, excel: { … }, popup: { … }, phoneBarConfig: { … },
    user: { … }, callBill: { … }, callRecord: { … }, km: { … },
    monitor: { … }, qualityCheck: { … }, questionnaire: { … }, sms: { … },
    email: { … }, weixin: { … }, webchat: { … }, push: { … },
    workbench: { … }, collect: { … }, notice: { … }, dept: { … },
    company: { … }, robot: { … }, role: { … }, channel: { … }, dic: { … },
    overallSituationConfig: { … }, interfaceUrl: { … }, tabUrl: { … },
    callEvent: { … }, callLabel: { … }, callInter: { … }, callUrl: { … },
    ivr: { … }, accountConfig: { … }, mailSign: { … }, channelDic: { … },
    account: { … }, customerCommon: { … }, customerApproval: { … }, …
};

exports.handleAction = function (action, session, res) {
    var actionFun = eval('actions.' + action.name);      // ★ 用 eval 做点分路径解析
    if (actionFun) {
        actionFun(action.data, session, function (result) {
            result.success = result.success || false;
            result.message = result.success ? (result.message || '200 ok!')
                                            : (result.message || 'unknow error!');
            utils.sendResult(result, res, action._aid);
        });
    } else { processUnknowAction(action, res); }   // "action[xxx] is not support!"
};
```

**重建提示**：`eval('actions.' + name)` 是安全隐患也是扩展点——换成 Map 查表即可，语义完全等价。
**接口规模实测：52 个命名空间 / 712 个 action（仅 cc-server-in 一个服务）**，这是"工作量"的硬指标。

### 1.3 响应

```jsonc
{ "success": true, "message": "200 ok!", "data": { … } }
{ "success": false, "message": "action[xxx] is not support!" }
```

### 1.4 Node → Java：同一套协议再转发一次

Node 侧的 `ccServiceUrl`（`http://127.0.0.1:9999/service`）收到的是**同样的 `action=` 语义**；
Java 侧 `AppHttpHandler` 用巨型 if/else 分派（cc-java-in 约 43 个分发点，yy-java-bill 约 54 个），
协议对象是 `C5Action` / `C5Response`。

```
浏览器 ──action协议──▶ Node(3000) ──action协议──▶ Java(9999) ──▶ MongoDB
```

⚠️ **这是整个系统最关键的架构事实**：想换 REST/Spring MVC，必须先写一层"action 协议适配器"，
否则 102 万行前端全部要改（详见 08 章）。

## 三、四类跳转（运营后台 → 产品）

**这是运营日常最高频的操作**：在计费中心（157:8000）选一个租户账号，点"跳转云客服/云电销/用户中心"。

配置在 **157 `/opt/yy-server-gddx/serverConfig.json`**：

| 跳转 | API 返回字段 | 前端落地字段 | 现值 |
|---|---|---|---|
| 云客服管理后台 | `ccServerUrl` | `ccServerUrl` | `http://192.168.1.156:80/` |
| 云客服 | `ccInUrl` | `ccInRedirect` | `http://192.168.1.156:80/` |
| 云电销 | `ccOutUrl` | `ccOutRedirect` | `http://192.168.1.156:8002/` |
| 用户中心 | — | `ucenterUrl` | `http://192.168.1.157` |

**用户中心跳转的实现细节（踩过坑）**：
1. 前端 form POST 到 `./public`，调用 `bill.getSessionId` 拿 sid；
2. 然后 `window.location = ucenterUrl + '/?sid=' + sid`；
3. **`ucenterUrl` 不能带尾斜杠**（带了会拼成 `//?sid=` 导致失败）。

⚠️ 两个反复验证过的坑：
- **Consul KV 不会覆盖本地 `serverConfig.json`**，改 Consul 无效，必须改文件并重启。
- **改完必须重启 yy-server**（配置启动时一次性加载）。

## 四、Asterisk 侧接口

### 4.1 AGI（ass 服务）

`agi://127.0.0.1:7891/<name>?<参数>`，TCP 7891，自研协议（`Banner=Hollycrm`）。

| AGI | 参数 | 作用 |
|---|---|---|
| `callinroute` | `did=<主叫>` | 呼入路由：定位租户与 PBX 实例 |
| `AgiCheckServiceNoType` | `Exten=<被叫>&pbx=<实例>` | 判定服务号/分机/外呼，返回 `ACCOUNT`、`extenType` |
| `AgiFormatDialoutNumber` | — | 外呼号码格式化（**加前缀 9**） |
| `gaicalllimit` | `pbx=<实例>&servicepeer=<服务号>` | 服务号并发与限额 |
| `agisiplogin` / `agisiplogout` | `pbx=<实例>` | 话机签入 / 签出 |
| `agibindexten` / `agibindquery` | `pbx=&exten=` | 绑定工号 / 查询绑定 |

### 4.2 AMI

`manager.conf` / `manager_additional.conf`，端口 TCP **6030**（156/159 均可见）。
监听/强插/强拆等班长操作**不在 dialplan 里调用**，应经 AMI 下发（`app_chanspy` + `app_meetme` 已加载）。

### 4.3 CDR

cccdr（8083）接收 Asterisk CDR，按 `handler.type=mongodb` 写入 Mongo（`cc` + `report` 库），
并回调 `hangup_sms_url=http://127.0.0.1:3000/`（挂机短信，模板在 `cc.cc_hangup_sms_template`）。

## 六、租户可配置的回调/扩展点（重要产品能力）

Mongo `cc` 库里这几张表是**租户级别的"低代码"扩展位**，重建时别漏：

| 集合 | 条数 | 能力 |
|---|---|---|
| `manager_interface_url` | 5 | 自定义外部接口地址 |
| `manager_call_url` | 5 | **通话中触发的 HTTP 回调** |
| `manager_dialout_url` | 2 | 外呼回调 |
| `manager_tab_url` | 4 | 客服工作台嵌入第三方页面（Tab） |
| `manager_interface_config_event` | 34 | 接口事件绑定（什么事件触发哪个接口） |

这是这套系统少见的、真正有价值的可编程能力。
