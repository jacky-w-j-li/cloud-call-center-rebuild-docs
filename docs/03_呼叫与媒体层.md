# 03 · 呼叫与媒体层（最不可替代的一章）

> 本章回答：**电话怎么打进来、怎么打出去、IVR 怎么编排、录音怎么落、坐席怎么注册。**
> 全部来自 159 测试机上 `/etc/asterisk/` 与 `asterisk -rx` 的实测输出。

## 一、Asterisk 多实例模型

**不是一套 Asterisk，是每台机上十几个独立实例**，每个实例一套配置目录 + 独立端口。

```
/etc/asterisk/
├── gateway/            ← 出局中继网关实例（UDP 5072）
├── gz.ydx.159.0/       ← 租户实例 0（UDP 6060）★ 488/489/490/491 四个租户都在这里
├── gz.ydx.159.1/ … .9/ ← 租户实例 1~9（UDP 6061~6069，accounts/ 全空）
├── gz.ydx.159.0_bak156/
├── mrcp.conf, res-speech-unimrcp.conf, run/
```

实例 0 的目录有 **76 个文件**，其中自己特有的：`extensions.ael`、`extensions_include.ael`、`extensions-sip.ael`、`accounts/`、各业务 `.conf`。

**`asterisk.conf` 决定一切目录**（多实例的关键）：
```ini
[directories]
astetcdir    => /etc/asterisk/gz.ydx.159.0
astmoddir    => /usr/lib/asterisk/modules
astvarlibdir => /var/lib/asterisk/gz.ydx.159.0
astagidir    => /var/lib/asterisk/agi-bin
astspooldir  => /var/spool/asterisk/gz.ydx.159.0      ← 非标准（录音在这里）
astrundir    => /var/run/asterisk/gz.ydx.159.0
astlogdir    => /var/log/asterisk/gz.ydx.159.0
[options]
systemname   = cc-ali-0
```

**必须用 `-C` 指定配置才能操作某个实例**：
```bash
asterisk -C /etc/asterisk/gz.ydx.159.0/asterisk.conf -rx 'sip show peers'
asterisk -C /etc/asterisk/gz.ydx.159.0/asterisk.conf -rx 'dialplan show'
```
（156 上则是 `gd.zj.1.0` 与 `gateway` 两个实例。）

**该版本无 `channel originate` 命令** —— 要触发 dialplan 测试，只能投递 call file：
```
Channel: Local/<exten>@<context>
```
spool 目录是 `/var/spool/asterisk/gz.ydx.159.0/`（不是默认的 `/var/spool/asterisk/`）。

**开机自启**（159 的 rc.local，逐实例启动）：
```bash
ulimit -n 65535
mkdir -p /dev/shm/astdb; touch /dev/shm/astdb/astdbgz.ydx.159.0
mkdir -p /dev/shm/monitorgz.ydx.159.0 /var/run/asterisk/gz.ydx.159.0 /var/spool/asterisk/gz.ydx.159.0
/usr/sbin/asterisk -g -C /etc/asterisk/gz.ydx.159.0/asterisk.conf
sleep 1
…依次 .1 ~ .9…
```

```

│   ├── announcement.conf  asr.conf  assignment.conf  auto_call_task.conf
│   ├── blacklist.conf  callurl.conf  dialjobnum.conf  dialout_line.conf

│   ├── service_no.conf  text_announcement.conf  time_condition.conf
│   ├── users.conf  validate.conf  voicemail.conf  xfer_line.conf
├── agi/  moh/  sound/
├── sip.conf                ← 真正的 Asterisk 分机配置（chan_sip）
├── queues.conf
├── moh.conf
└── *.ael                   ← 29 个节点**逻辑**模板
    announcement.ael  asr.ael  assignment.ael  blacklist.ael  callroute.ael
    callurl.ael  date_node.ael  dialexten.ael  dialjobnum.ael  dialout.ael
    dynamicroute.ael  encrypt_md5.ael  extension_peer.ael  extensions.ael
```

**这就是 29 类 IVR/话务节点的完整清单。** 每个节点类型 = 一个 `.ael` dialplan 模板 + 一个同名 `.conf` 数据文件 + Mongo 里的一张 `manager_ivr_*` 表。
【推断】`ass` 服务负责把 Mongo/`.conf` 里的数据渲染成 `.ael` 并 reload；页面改 IVR 后能"立刻生效"就是这个链路。

> ⚠️ 记忆里此前记为"28 个节点"，实测 **29 个 .ael**（另有独立的 `conf/nums.conf`、`redlist.conf` 等纯数据表）。

### 2.2 Context 命名规则（实测 `dialplan show`）

```
<租户ID>-<节点ID>-<节点类型>      例：N00000000489-10214-ivr-menu
                                    N00000000489-10015119-queue
                                    N00000000489-10241-dynamic-route
                                    N00000000489-10199-ExtensionPeer
<租户ID>-<语义>                   例：N00000000489-dialout / -predialout / -transferout
                                    N00000000489-route / -investigate / -dialin
                                    N00000000489-balance / -call / -dial
<服务号>                          例：02022221112（及其 -ivrlogin/-ivrlogout/-ivrlogined/
                                                  -jobnumconfirm/-jobnumconfirmout）
sip-login / sip-logout / sip-bind / sip-query / sip-manage   ← 话机签入签出全局 context
```

队列节点会一次生成 4 个 context：`-queue`、`-queue-empty-transfer`、`-queue-wait-transfer`、`-queue-hangup-transfer`（分别对应：排队中、队列空、等待超时、来话挂断）。

## 三、呼入全流程（实测 dialplan）

### 3.1 入口 `context default`

```ael
context default {
  _. => {
     FROM_CID = ${CALLERID(num)};
     calledNumber = ${EXTEN};
     FROM_DID  = ${EXTEN};
     if ("${FROM_DID:0:6}" == "446488") {          // 中继送来的特殊前缀
        CalledNo = ${FROM_DID:6};                  // 剥前缀
        Agi(agi://127.0.0.1:7891/callinroute?did=${FROM_CID});
        if ("${domain}" == "0") {                  // 用 History-Info 头二次解析真实被叫
           History-Info0 = "${SIP_HEADER(History-Info)}";
           … Agi(callinroute?did=${History-Info2}) …
        }
     }
     Agi(agi://127.0.0.1:7891/AgiCheckServiceNoType?Exten=${FROM_CID}&pbx=${HOST});
     …
  }
}
```

### 3.2 服务号 context `02022221112`（逐行实测）

```
1. Wait(0.5)
2. Set(FROM_CID=${CALLERID(num)})       ← 主叫
3. Set(FROM_DID=${EXTEN})               ← 被叫（服务号）
4. Set(FROM_CONTEXT=${CONTEXT})
5. Set(ACCOUNT=N00000000489)            ← 租户在 dialplan 里写死
6. Set(SERVICE_NO_TYPE="normal")
7. Wait(0.5)
8. Agi(agi://127.0.0.1:7891/gaicalllimit?pbx=${HOST}&servicepeer=02022221112)  ← 并发/限额
9. Answer()
10. Wait(1)
11-16. 按主叫号码分流（013822221111 / 13822221111 → 02022221112-ivrlogin，即"自己人打进来走签入流程"）
17. [loop] Goto(N00000000489-10220-blacklist|${FROM_CID}|1)   ← 黑名单
```

### 3.3 呼入链路汇总

```
PSTN/中继 → gateway(5072) → 租户实例(6060) context=default
  → AGI callinroute（按主叫/被叫定位租户实例）
  → AGI AgiCheckServiceNoType（判定 服务号 / 分机 / 外呼）
  → context <服务号> → AGI gaicalllimit（并发与限额）
  → Answer → 黑名单 → 时间条件 → IVR 节点链（菜单/语音/ASR/动态路由/HTTP/工号/技能组）
  → Queue() 技能组排队（ringall / fewestcalls 等策略）
  → 坐席 SIP 分机振铃 → 接通 → Monitor() 录音
  → 挂机 → AGI 写话单 → cccdr(8083) 落 Mongo(report 库) → 报表聚合
```

## 四、坐席与分机模型（三个 ID 千万别混）

| 概念 | 例子 | 载体 |
|---|---|---|
| **工号 Exten** | 8030、8025 | `users.conf` 的 `[段名]`；**不是端口** |
| **SIP 分机号** | 20008660 | `sip.conf` 的 `[段名]`；话机实际注册的账号 |
| **坐席 UUID** | `f20f3bf0-13bf-11ee-...` | Mongo `app_extension_config.UserID` / `users.conf` 的 `id=` |

### 4.1 `users.conf`（应用自己的坐席配置，**不是** Asterisk 的 users.conf）

```ini
[8030]
id=f20f3bf0-13bf-11ee-aaf3-9d0b35a86868     ← 坐席 UUID
Password=1234Qwer
AutoBusyTime=0
Exten=8030
Local=13822221111                            ← 绑定的手机号（外呼时做主叫）
DisplayName=8030
OwnSipNums=sip:20008660,gateway:20008671,Local:20008661   ← 名下的号码
Version=enterprise
UCExtenType=sip
CallerIDNum=02022221112                      ← 外呼显示的主叫号码
DialoutType=
```

**`OwnSipNums` 前缀含义**：`sip:` = 软/硬话机分机；`gateway:` = 出局中继分机；`Local:` = 绑定的手机（手机直呼场景）。

### 4.2 `sip.conf`（真正的 chan_sip 配置）

```ini
[20008654]                      ← SIP 分机号
type=friend
nat=yes
canreinvite=no
call-limit=1
qualify=yes
context=N00000000489            ← ★ 决定"从这个分机打出去走哪个 dialplan context"
callerid="20008654"<20008654>
disallow=all
allow=alaw
allow=g729
allow=gsm
secret=jgi2r8yi
host=dynamic
c5local=no
ExtenType=sip                   ← ★ sip / gateway / Local
c5user=77981cc0-0b54-11ee-a8c9-9918b065328b   ← 所属坐席 UUID

[20008655]                      ← 绑定手机的"Local"分机
type=friend … context=Local-NO-Permission
host=192.168.1.159  port=5072
username=N00000000489009613822221111
fromuser=U77981cc0-...null
localnum=13822221111
ExtenType=Local
```

**⚠️ 三条铁律（反复验证过）**：

1. **`ExtenType=gateway` 的分机 `allow=g729` 独占** —— 软电话（MicroSIP）不支持 G.729，会出现「注册成功但呼叫 `No compatible codecs`、无声、CDR `STATUS=leak`」。**软电话必须注册 `ExtenType=sip` 且带 alaw 的分机。**
2. **坐席分机的 `context` 都是 `<租户ID>`，不是 `default`** —— 所以坐席话机**拨不进服务号/IVR**。
3. **只有 `sip_test.conf` 里的 5001/7moorcom 是 `context=default` 且带 alaw** —— 想以"呼入"身份进服务号流程做测试，只能用这个号。

## 五、AGI 服务（ass）

`ass` 是 **Java 6 + OSGi/Equinox**（`/opt/ass/equinox.jar`，1,186 个源文件，40+ bundle），
在 **127.0.0.1:7891** 提供 TCP AGI 服务（自研协议，`agi_tcp_server.conf` 里 `Banner=Hollycrm`、`MaxConnection=2000`、`DispatcherNum=50`）。

dialplan 里出现过的 AGI 入口（全部走 `agi://127.0.0.1:7891/<name>`）：

| AGI | 作用 |
|---|---|
| `callinroute` | 按 `did`（主叫/被叫）定位租户与 PBX 实例 |
| `AgiCheckServiceNoType` | 判定被叫是服务号/分机/外呼，返回 `ACCOUNT`、`extenType` |
| `AgiFormatDialoutNumber` | **格式化外呼号码（会加前缀 9）** |
| `gaicalllimit` | 服务号并发与限额控制 |
| `agisiplogin` / `agisiplogout` | 话机签入 / 签出 |
| `agibindexten` / `agibindquery` | 话机绑定工号 / 查询绑定 |

`ass` 还负责：写租户 `.ael`/`.conf`、管理 CDR、号码黑名单（`allblacknums.conf`）、离线坐席（`offLineUser.conf`）、监听服务（`monitor_server.conf`）。

## 九、媒体层硬约束（重建必读）

| 约束 | 实测值 | 后果 |
|---|---|---|
| **RTP 端口范围** | `rtpstart=10000 / rtpend=10005`（**6 个端口**） | 并发约 **3 路**。必须改成 `10000-20000` |
| **编码** | `disallow=all; allow=g729; allow=alaw`（gateway 侧同样） | G.729 有专利，Asterisk 新版默认不带 |
| **多实例端口写死** | 6060~6069、5072 | 话机里写死地址，改端口=要重配所有话机 |
| **无 `channel originate`** | 1.4 老版本 | 自动化测试只能投 call file |
| **spool 非标准** | `/var/spool/asterisk/<实例名>/` | 备份/容器挂载别漏 |
| **`/etc/asterisk` 需可写** | 页面改 IVR 会写回 `.ael` 并 reload | 容器化必须 RWX PVC |
