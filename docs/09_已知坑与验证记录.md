## 一、八条铁律（反复验证过）

1. **外呼会加前缀 9**
   分机 context 的 `_X.` → AGI `AgiFormatDialoutNumber` 加 9 → 路由匹配不上 → 落到 `MusicOnHold()`。
   **判定方法**：看 CDR 录音名是否带 9 前缀（拨 `02022221112` → 录音名 `902022221112`）。
   **后果**：软电话拨不进 IVR/内部节点，表现为"打通了但没声音"。

2. **想以"呼入"身份进服务号流程，只能用 `sip_test.conf` 的 5001**
   `5001/7moorcom`，`context=default`，是 5000~5007 里**唯一带 alaw** 的。
   注册到 `159:6060` 后拨服务号即可。**坐席分机的 context 都是 `<租户ID>`，不是 default，拨不进。**

3. **`ExtenType=gateway` 的分机 `allow=g729` 独占**
   MicroSIP 不支持 G.729 → 注册成功，但呼叫报 `No compatible codecs`、无声、CDR `STATUS=leak`。
   **软电话必须注册 `ExtenType=sip` 的分机。**

4. **159 上操作 Asterisk 必须带 `-C`**
   `asterisk -C /etc/asterisk/gz.ydx.159.0/asterisk.conf -rx '...'`（多实例）。
   该版本**没有 `channel originate`** → 测 dialplan 只能投 call file（`Channel: Local/<exten>@<ctx>`）。
   spool 目录非标准：`/var/spool/asterisk/gz.ydx.159.0/`。

5. **156 和 159 都用 UDP 6060**
   别凭 IP 猜 PBX，一律以数据里的 `PBX` 字段为准。

6. **业务服务不向 Consul 自注册**
   `start_cc.sh` 只起 agent；`/etc/consul.d/services.json` 为空；现有 9 个服务是历史 API 注册留在
   `/opt1/consul/data/services` 的**僵尸注册**。**且 Consul KV 不覆盖本地 `serverConfig.json`**（改 KV 无效）。

7. **改 `serverConfig.json` / `server.conf` 必须重启服务**（启动时一次性加载）。

8. **157 上跑的代码与本地源码树不一致**（`自建/yy-server` vs 157 实际：`redirectCCInLogin` 一个用 `ccServerUrl` 一个用 `ccInUrl`）。
   → **以服务器为准**；任何重构前先做源码版本对齐。

## 三、排障方法论（可复用）

### 3.1 定位一通电话走了哪

```
1) 通话记录里取 PBX 字段（不要凭 IP 猜）
2) 找对应实例：asterisk -C /etc/asterisk/<实例>/asterisk.conf -rx 'dialplan show <被叫>'
3) 看 context 链：服务号 context → blacklist → IVR 节点 → queue
4) 坐席定位：DISPOSAL_AGENT(UUID) → accounts/<租户>/conf/users.conf 的 id= → OwnSipNums
5) 录音名反推：monitor/<PBX>/<日期>/<时间>_<租户>__<被叫>_<systemname>-<uniqueid>.mp3
```

### 3.2 验证 dialplan 改动

```bash
# 该版本无 channel originate → 投 call file
cat > /var/spool/asterisk/gz.ydx.159.0/tmp/test.call <<'EOF'
Channel: Local/02022221112@default
Context: default
Extension: s
Priority: 1
EOF
```

### 3.3 UDP/SIP 探测

**别收到第一个包就 close** —— Asterisk 会先回 `100 Trying`，再回 `401/200`。

## 四、改造类评估的实测结论（避免重复踩坑）

### 4.1 Java 17 编译（2026-10-20 实测）

**14 个工程、1,872 个源文件，JDK 17 下 100% 编译通过**；`report-java` 打包 19.98MB 且**实机启动成功**
（Mongo 驱动、10 个线程正常初始化，stderr 零输出）。

编译期问题只有 5 类，**全部机械可修**（共改 21 个文件约 20 处）：

| 类型 | 修法 |
|---|---|
| `sun.misc.BASE64Encoder/Decoder` | 换 `java.util.Base64`；多数是**未使用的残留 import**，直接删 |
| `sun.misc.Regexp` | 只有 import 没使用 → 删 |
| POI `Record` 撞 `java.lang.Record`（JDK16+） | 按需导入造成平级歧义 → 加一行显式 `import org.apache.poi.hssf.record.Record;` |
| `com.sun.org.apache.xpath.internal.operations.Bool` | **IDE 误导入**（代码其实用 `Boolean`）→ 删 |
| `sun.net.ftp.FtpClient` | **唯一真改造**：`yy-java-bill` 是 JDK6 老 API，而**同项目的 `yy-java-timer` 已是 JDK7+ 新写法**且签名一致 → 直接复用 |

**编译适配仅约 1.5 人天**。→ 结论：Java 升级从"可能做不了"变成"确定能做，成本在测试"。

**推翻的旧判断**：此前记的"`com.sun.net.httpserver` 需要 `--add-modules jdk.httpserver`"是**错的** ——
实测那 8 处引用全在**注释和 Logger 字符串字面量**里，且各工程自带 httpserver 克隆实现（`ds/net/httpserver/ServerImpl.java`）。

**三件还没做的事**：
1. **cc-ass 未验证**（1,186 文件，OSGi/Equinox，40+ bundle，无 pom/build.xml，靠 MANIFEST.MF Import-Package）→ **唯一真正的未知数**。
2. 其余 13 个工程未做 JDK 17 启动冒烟（XStream 1.3.1 重度反射在 JDK16+ 强封装下有风险）。
3. **必须回归 2 处**：`cc-cdr/HttpUtil` 的阿里云 ASR 签名（`sun.misc` Base64 每 76 字符插 `\n`，`java.util` 不换行 = **行为变更**）、`yy-java-bill` 的 FTP 上传下载。

### 4.2 Spring 化（2026-10-22 实测）

**结论：技术可行，但"全部转 Spring"投入产出不成立。**

- **命门是协议**：`action=xxx&data={}` 私有 RPC **贯穿 前端↔Node↔Java**。Spring MVC 是 REST 范式，不兼容。
  → 要么写协议适配层（保前端），要么连 **102 万行前端**一起改。
- **两个好消息**：① Java 17 前提已免费拿到（见 4.1）；② **`javax.servlet` 零使用**（当年用自研 httpserver，反而躲过 Jakarta 迁移大坑，只有 `javax.mail` 25 处要换）。
- **硬阻塞**：测试环境 MongoDB ≈3.2（原厂推荐配置见 19 篇，不代表真实生产版本），Spring Data Mongo 4.x 要求 4.0+ → **Boot 3 落地前必须先升 Mongo**（15~30 人天）。
- **建议范围**：Java 层 200~280 人天（值得做）；**Node 层不要转 Java**（独立升 Fastify/NestJS 只要 20~40 人天）；
  **cc-ass 别碰**（实时信令重写风险太高）。

### 4.3 K8S 化

- 三台合计 5 核 8G + 157 内核 2.6.32 → **硬件判死**，不换硬件跑不了 K8S（最小 3×4C8G）。
- cgroup v1 → K8S 版本锁 **1.28~1.30**。
- Asterisk 用 **DaemonSet + `hostNetwork:true`**（话机写死了 IP/端口，不能变）；**不追求多副本**（chan_sip 不支持共享注册）。
- **`/etc/asterisk` 必须 RWX PVC**，不能放 ConfigMap（页面改 IVR 会写回 .ael 再 reload）。
- 路线：治理(5~8) → Docker 化(15~20) → K8S(30~45)，**媒体层建议留在 VM**。

### 4.4 迁 AWS + 全量升级

- Asterisk **21 删 `chan_sip` 且删 `res_monitor`**（现网 `Monitor(wav,...)` 全部失效 → 必须改 `MixMonitor`）。
  同批删除/弃用：`app_macro`(→Gosub)、`app_cdr`、`users.conf`；`MeetMe`→`ConfBridge`。
- 升 **Asterisk 20 LTS** 两步走（20 仍有 chan_sip → dual-stack 迁 PJSIP → 再考虑 22）。
- **G.729 新版默认不带**（专利）→ gateway 分机 `allow=g729` 是业务改造项。
- AWS 网络硬规则：SIP/RTP 节点**必须在公网子网 + 可路由公网 IP**（SDP 通告真实地址，NAT GW 只出不进）；**UDP 只能 NLB**。
- 成本：按需 ≈ $5,100/月；RTP 出网流量是长期可变成本（100 路并发 ≈ 2.8TB/月 ≈ $250）。

## 五、本机工具链的坑（做二次开发时会遇到）

- **Node**：`C:\Users\amyren\.workbuddy\binaries\node\versions\22.22.2-6\node.exe`
  （ssh2 模块在 `C:\Users\amyren\.workbuddy\binaries\node\workspace\node_modules\ssh2`，需绝对路径 require）。
- **JDK 17**：`D:\Backup\Users\amyren\.jdks\corretto-17.0.12\bin\{javac,java,jar}.exe`。**本机无 JDK 21，PATH 里没有 java**，必须用绝对路径；**本机无 Ant**（用等价 javac 复现 `build.xml`）。
- **PowerShell 5.1 两个坑**：
  1. `Start-Process` 会因环境里 `HTTP_PROXY`/`http_proxy` 大小写重复报"字典键冲突" → 改用 node `spawn`。
  2. 脚本块换行传参 + 复杂正则会 parse error → **批处理一律用 node 写 `.cjs`**。
- **jar 打包**：MANIFEST.MF 单行 ≤ 72 字节，手拼 `Class-Path` 会报 `line too long`，须折行（续行以单个空格开头）。
- **ssh2**：`algorithms.serverHostKey` 里不要写 `ed25519`（会报 Unsupported algorithm，让库自己协商）。
- 可复用脚本：`D:\lwj\workspace\_compile_r2.cjs`、`_fix_round1.cjs`、`_fix_round2.cjs`；
  本次采集用的通用 SSH 批量执行器：`D:\lwj\_doc\ssh.cjs`（`node ssh.cjs <job.json> <out.txt>`）。
