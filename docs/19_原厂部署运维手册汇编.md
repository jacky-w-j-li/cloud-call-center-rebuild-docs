## 19.1 开户流程（★ 11 步，原厂规范）

**计费运营系统地址**：`https://user.7moor.com:9000/`（公有云）/ `http://14.29.4.228:8000`（自建）

### 两条铁律

1. **新增完账户之后，必须开通相应的「产品」**才能有对应的云客服系统；
2. **必须绑定 PBX 之后**才能有坐席和语音功能。

### 操作步骤

| # | 在哪 | 路径 | 填什么 | 产出 |
|---|---|---|---|---|
| 1 | 计费运营系统 | 系统菜单 → 账户管理 → 添加账户 | 公司名称=客户公司全称；**账号名称=客户拼音简写**（自建版填**经销店代码**）；密码=自动生成；联系人信息 | 租户账号 |

| 3 | 计费 → 跳转云客服 | 设置 → 高级功能 → 通话配置 → 添加 pbx | 选目标 PBX；**把「通话事件」和「轨迹」选上** | 租户与 PBX 绑定 |
| 4 | 计费运营系统 | 账户 → 充值 | 不需要计费的话**充多一点值** | 余额 |
| 5 | 计费 → 服务号管理 | 添加号码 → 跳转用户中心 → 呼叫中心 → 选号 → 状态改「在用」 | **类型必须选「正式」**；号码从运营商获取 | 服务号/外显号码 |
| 6 | 计费 → 用户中心 | 呼叫中心 → 坐席 licence 设置 → 新增 licence | 选**企业版** → 状态「在用」 → 改数量 → 到期时间改长 | 坐席 license |
| 7 | 云客服 | 设置 → 高级功能 → 通话配置 → 外呼线路配置 | 外呼线路与呼转线路的**透传号码都选步骤 5 的号码** | 出局线路 |
| 8 | 云客服 | 设置 → 高级功能 → 客户配置 → 添加客户数据库 | 随便填，添加了就行 | 客户库 |
| 9 | 计费运营系统 | 账户 → 产品 → 呼叫中心并发设置 | 座席透传并发、多透传并发**设大一点（如 100）**；**最后面三个并发选 -1（不控制）** | 并发配额 |
| 10 | 云客服 | 部门坐席配置 → 批量添加座席 | 选**企业版**；**账号和密码设成一样**；**一般从 8025 开始，8025 设为管理员** | 分机号/工号 |
| 11 | 客户端 | 测试呼入呼出 | 选择 `pc+phone`，phone 号码选手机 | 验收 |

### 关键约束

| 项 | 原文 |
|---|---|
| licence 与座席数 | **新增的 licence 需与座席数、座席使用产品保持一致，否则座席无法登录成功** |

## 19.2 PBX 部署

### 19.2.1 安装脚本执行顺序（原文命令）

```bash
tar xzvf tools.tar.gz                  # 或把测试环境 /tools 拷到新机
yum -y install dos2unix
cd /tools/
dos2unix install_base.sh               # 必须转码
sh install_base.sh pbx
yum -y install kernel kernel-devel
reboot                                 # 装完内核必须重启

mkdir -p /data/asterisk/spool/asterisk
mkdir -p /data/asterisk/log/ass
mkdir -p /data/asterisk/log/asterisk
mkdir -p /data/asterisk/log/asteriskGuard
ln -s /data/asterisk/spool/asterisk /var/spool/asterisk
ln -s /data/asterisk/log/ass          /var/log/ass
ln -s /data/asterisk/log/asterisk     /var/log/asterisk
ln -s /data/asterisk/log/asteriskGuard /var/log/asteriskGuard

cd /tools/
sh asterisk_install7-11.sh pbx         # 需把 ssh 窗口最大化；提示选择时选 A 回车
vim config_mrcp.sh                     # 改 ip= 与 n_ip= 为本机地址
sh  config_mrcp.sh -s 0 -e 9 -n "gz.yhw.65"
```

### 19.2.2 实例命名与数量

- **一个 asterisk 进程 = 一个实例**，配置目录如 `/etc/asterisk/gz.yhw.65.0`
- `-s 0 -e 9` → **一般一台 PBX 有 10 个坐席实例**（`.0` ~ `.9`）
- `-n "gz.yhw.65"`：`gz` = 广州 020 区号，**最好不要改前面的 gz**；末段是**每台机器唯一**的
- `/etc/asterisk/gateway` 是**路由实例**，一般不需修改
- **每台 PBX 的实例名字都配置成不一样**

### 19.2.3 ass（状态服务器）部署

| 项 | 原文 |
|---|---|
| 目录 | `/opt/ass/` —— **需要从正常运行的 PBX 里复制一份过去** |
| 配置 | 改 `server.conf` 的 `[server]` 段 |
| `dialout.line` | `-dialout.line=10.168.4.66` —— **本机内网地址** |
| `fileServer` | `-fileServer=http://10.66.220.84` —— **录音地址，网页访问，一般公网** |
| 启动 | **必须使用全路径**：`nohup /opt/ass/ass.sh restart &` |
| 自启动 | ass 安装好后会设置开机启动 |
| 日志 | `/var/log/ass` |

### 19.2.4 端口与目录

| 端口 | 用途 |
|---|---|
| **7789** | rest 接口服务实际监听 |
| **17789** | nginx 对外转发端口 → **转发到 7789**；配置地址必须填 17789，"不然 rest 接口服务会出错" |
| RTP 范围 | 在 `rtp.conf` 里配置 |

> **nginx 版本要用安装包安装的版本，最新的版本可能会有问题。**

### 19.2.5 计费运营系统中登记 PBX

| 步骤 | 路径 | 填写要点 |
|---|---|---|
| pbx 管理 | 呼叫中心 → pbx 管理 → 添加 pbx | **ass 地址**和 **sip 地址** = pbx 的**公网地址**（座席网页连这个）；**config 地址（用 17789）** 和 **路由 ip** = pbx **内网地址** |
| 机柜管理 | 呼叫中心 → 机柜管理 → 添加 | 先在**机器管理**添加 pbx，再在**外呼中继**和**外呼路由**里生效 |

### 19.2.6 Asterisk 网络配置要点（重要）

1. 坐席实例 `sip.conf` 的 **`externip` 需改成坐席侧的服务器公网地址**；
2. **一个 asterisk 实例只能绑定一个公网地址** → 建议**一个 PBX 绑定一种网络的公网地址**；
3. 每个 PBX 需绑定一个公网地址，**跟内网地址一一对应**；该公网地址需能 **UDP 外访任意公网地址**，并**被任意公网地址以 UDP 访问**；
4. **坐席用电信/联通/移动哪种网络连过来，账号就建在绑定哪种公网地址的 PBX 上** → 三种公网网络就需要**三个 PBX**。

### 19.2.7 clpms（即 FreeSWITCH）

| 项 | 原文 |
|---|---|
| 获取 | 直接从其它 PBX 复制，默认目录 **`/data/clpms`**；也可用网上下载的 freeswitch 代替 |
| 用途 | 转发运营商云中继的 SIP 通话到 PBX，**主要作用是内外网 RTP 转发**（根据被叫前缀判断呼入/呼出）。**都是内网的话不用也可以** |
| 呼入 | `云中继 → clpms(freeswitch) → asterisk(gateway) → asterisk(实例)` |
| 呼出 | `asterisk(实例) → asterisk(gateway，被叫加前缀 096) → clpms(识别 096 转云中继) → 云中继` |
| 关键参数 | `/data/clpms/conf/sip_profiles/` 下 `external.xml`、`internal.xml` 的 **`ext-rtp-ip`** 与 **`ext-sip-ip`**（与 NAT 有关） |
| 对接配置 | `/data/clpms/conf/sip_profiles/external/gateway.xml`、`autoload_configs/acl.conf.xml` |
| 日志 | `/data/clpms/log` |

### 19.2.8 ⚠️ crontab 与自启动的坑（原文摘录）

> 1) 安装脚本会写指令到这几个文件的最后：`/etc/rc.local`、`/etc/profile`、`/root/.bashrc`。**重新执行安装会重复加入指令**，最好看看这几个文件内容有没有重复；
> 2) 重新执行安装后，**查看 crontab 的脚本是否有重复，有就删除**。**crontab 的脚本是监控进程的**，可根据实际情况修改。

### 19.2.9 进程、控制台、日志

| 项 | 说明 |
|---|---|
| 进程 | **1 个 gateway 进程 + 10 个实例进程** |
| 控制台 | `rasteriskg`（路由实例）；`rasterisk0`（座席 0 实例，1~9 类推） |
| 日志 | asterisk 在 `/var/log/asterisk` 下**每实例一个子目录**；ass 在 `/var/log/ass`；clpms 在 `/data/clpms/log` |

### 19.2.10 网络压测结论（iperf3）

```bash
iperf3 -s                                          # 服务端
iperf3 -c 10.168.4.65 -u -b 30M -l 160 -P 10       # 客户端
```
**上限约 300M；每路通话占用 100K；一台 PBX 约可支持 3000 路通话，再高会丢包。**
> 原厂结论：**PBX 服务器的网络性能是瓶颈。**

### 拨测指引（6 项）

1. 外网登录，管理员账号 `8020@<租户>`；**选择 `pc+phone`，phone 号码选手机**
2. 管理员在设置中查看发送的主叫号码数据
3. 填入外呼被叫号码，点击外呼，系统弹屏被叫号码的呼叫记录
4. **实际呼叫时序**：PC+PHONE 的手机先振铃，来电号码 `02082290120` → 按接听 → 被叫号码振铃，来电号码同样是 `02082290120`
5. 查看该 vdn 工号坐席配置数据
6. 修改 phone 手机：设置 → 部门坐席配置 → 找到工号 8020 → 修改手机后保存

## 19.5 架构与服务清单（原厂）

### 19.5.1 三类用户

| 角色 | 说明 |
|---|---|
| 运营人员 | 主要用计费系统，管理账户、计费、配置 |
| 坐席人员 | 登录应用系统 cc，处理电话/工单/微信/在线咨询/邮件；**登录后与平台建立推送长连接** |
| 终端客户 | 通过多渠道接入与坐席交互 |

### 19.5.2 主要服务职责

| 服务 | 职责 |
|---|---|
| **bill** | 平台运营计费系统，管理资源、客户、费用控制、接入配置，**整个系统的管理后台** |
| **Cc** | 云客服系统（坐席终端）：通话记录、录音、客户、工单；管理员可见实时监控与报表 |
| **PushServer** | 坐席登录用 H5 **websocket** 建长连接；浏览器不支持则**自动转长轮询** |
| **Pbx/Ass** | 从 PSTN 以 **SIP 信令**接入，在 pbx 做**软交换 & IVR**，最终把电话和坐席接通；实现电话软交换 & CTI |
| **微信服务** | 实现微信公众平台开发接口，接收消息推送、发送客服消息 |
| **在线咨询服务** | 网站/APP 咨询消息处理与接入（**手机网站走 websocket，APP 走 tcp 长连接**） |
| **邮件服务** | 接收客服邮箱转发来的邮件，分解附件、处理内容后推送；代发 |
| **Gateway** | 消息网关，对接多渠道消息，**统一格式**，保证数据一致性 |
| 报表 / 日志 / 提醒 / 排队 / 大数据 | 实时报表运算、健康预警、通知、消息排队、数据分析 |

### 19.5.4 技术栈（原厂表述）

| 层面 | 技术 |
|---|---|
| 架构风格 | 互联网**微服务架构** |

## 19.6 高可用方案（原厂）

**技术选型（原文首行）**：`nginx 做负载均衡，mongo 分片集群，redis 主从+哨兵，elasticSearch 使用双节点`。

| 组件 | 冗余方式 | 机器数 | 要点 |
|---|---|---|---|
| **应用服务** | 4 台，**每台都部署所有应用服务** | 4 | 负载均衡 + 高可用 |
| **nginx** | 4 台都部署 | 4 | 反向代理与负载均衡 |
| **Consul** | **consul 集群** | 4 | 后端服务间负载均衡；**服务启动时自动注册**；**实时更新 consul-nginx 配置并重启**，实现自动服务发现 |
| **前端入口 LVS** | **lvs 分发用户请求到不同 nginx** | — | 静态资源返回 |
| **前端→后端** | nginx 配置**两个后端节点**，一个挂另一个仍可服务 | — | 例：cc-client-vue → cc-server-in |
| **后端→后端** | 请求通过 **consul 中的 nginx** 反代到目标服务 | — | 例：cc-server-in → gateway |
| **MongoDB** | **分片集群**（Sharded cluster） | 3 台 + 每台应用服务器部署 mongos | 主挂后**从节点被仲裁节点选举为新主**，应用无感知；复制集保证高可用，分片保证可扩展 |
| **Redis** | **主从 + 哨兵** | 2 台 | nginx 配置**主备模式**：主健康全部分发到主；主挂后哨兵选新主并**修改 nginx 主从节点信息** |
| **ElasticSearch** | **双主模式 + nginx 负载均衡** | 2 | 两个节点都是主，访问任意节点服务相同 |

### 混合云方案要点（话务下沉本地）

| 维度 | 要点 |
|---|---|
| 适用 | 自有运营商线路（sim 卡网关 / 模拟中继 / NGN / IMS）、通话数据安全、职场网络苛刻 |
| 形态 | **话务服务器在本地，话务数据与录音都在本地**；其余用云服务；**不受外网波动影响** |
| 并发能力 | 企X宝 7M-30 **最低 30 路并发 + 1 根 E1**；7M-240 **最高 240 路并发 + 8 根 E1**；**服务器堆叠可横向无限扩展** |
| 线路 | E1 支持 **PRI（优先）及 7 号信令**；SIP 支持 **NGN、IMS** |
| 机房 | 服务器需**固定 IP**，接入外网（带宽无硬性要求）；坐席电脑、话机、话务服务器**可互相访问**；**防高温、防尘、UPS** |
| 上线周期 | 采购 2-3 天 → 开户配置 → 设备到货 2-3 天 → 物流 → 远程装配调试（**整体约 5 个工作日**） |
| 售后 | 7×24 免费支持；**企X宝 3 年内硬件故障免费换新，3 年后 5 折换新** |
