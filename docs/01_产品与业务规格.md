## 一、四条产品线

系统实际是**四套前台 + 一套后台**，共用同一批数据与呼叫引擎：

| 产品线 | 入口 | 使用者 | 职责 |
|---|---|---|---|
| **云客服（cc-in）** | `http://192.168.1.156:80/` | 客服坐席、班长 | 呼入接听、在线咨询、邮件/微信、工单、客户、质检、报表 |
| **云电销（cc-out）** | `http://192.168.1.156:8002/` | 电销坐席 | 外呼任务、批量外呼、客户跟进、跟进状态审核 |
| **云客服管理后台** | `http://192.168.1.156:80/`（管理员角色进入） | 租户管理员 | IVR/服务号/技能组/坐席/角色 等全部配置 |
| **计费/用户中心** | `http://192.168.1.157:8000/` | 平台运营 | 开户、套餐、充值、账单、租户跳转 |

进入方式是「**运营在计费中心选一个租户账号 → 点跳转 → 带着 sid 落到对应产品**」（详见 05 章四类跳转）。

## 二、角色与权限模型

权限不是简单的菜单显示/隐藏，而是三层：`limits`（功能点） + `scope`（数据范围） + 产品线维度（in/out）。

**测试环境实测的角色文档** `cc.app_role`（340 条，系统内置 3 个）：

```jsonc
{
  "_id": "0c250380-bdc8-11e6-982f-6902d0da3c12",
  "accountId": "N00000000428",
  "display_name": "座席",
  "type": "system",              // system=系统内置 / custom=自建
  "identity": "agent",           // agent / admin ...
  "limits": ["call","my_call","incoming_call","my_call_sheet","customer","business", ...],
  "limits_in":  ["nav_workbench","nav_call","func_cdr_search","nav_webchat", ...],
  "limits_out": ["nav_workbench","nav_call","nav_customer","nav_dial_task", ...],
  "scope": "level",              // 数据可见范围：level=按组织层级
  "scope_in":  { "call":"level", "customer":"level", "business":"level",
                 "chat":"level", "email":"level", "sms":"level",
                 "qc":"level", "question":"level" },
  "scope_out": { "call":"level","customer":"level","business":"level",
                 "custTask":"level","custApproval":"level","sms":"level" }
}
```

要点（重建时必须实现）：
1. **同一角色在客服/电销下的权限是两套**（`limits_in` / `limits_out`），不是复用一份。
2. **数据范围按"组织层级"控制**（`scope: level`），坐席只能看本部门及下级的数据；另有 `platform_department`（128 条）承载组织架构。
3. 权限点命名有规律：`nav_*` = 一级导航，`func_*` = 页面内操作按钮。

**四类典型角色**（【推断】基于 role 文档与菜单）：平台运营（计费后台）、租户管理员、班长/质检员、普通坐席。

## 五、核心业务流程

### 5.1 呼入（电话打进服务号）

```
主叫 → 中继/网关（gateway:5072，trunk polylink-international → 47.90.45.121）
   → Asterisk 实例（159 上 UDP 6060~6069 之一）context=default
   → AGI: callinroute?did=${CALLERID(num)}        // 按主叫号码路由到租户实例
   → AGI: AgiCheckServiceNoType?Exten=...&pbx=...  // 判定被叫是"服务号"还是"分机"
   → 跳到 context <服务号>（例如 02022221112）
   → AGI: gaicalllimit?servicepeer=02022221112      // 并发/限额检查
   → Answer() → 黑名单 → IVR 流程节点链（见 03 章）
   → 技能组队列 Queue() → 坐席振铃 → 通话建立 → Monitor() 录音
   → 挂机 → AGI 写 CDR → cccdr 落库 → 报表聚合
```

实测 `dialplan show 02022221112`（159 上真跑的流程）：
```
1. Wait(0.5)                    6. Set(SERVICE_NO_TYPE="normal")
2. Set(FROM_CID=${CALLERID(num)}) 7. Wait(0.5)
3. Set(FROM_DID=${EXTEN})       8. Agi(agi://127.0.0.1:7891/gaicalllimit?pbx=...&servicepeer=02022221112)
4. Set(FROM_CONTEXT=${CONTEXT}) 9. Answer()
5. Set(ACCOUNT=N00000000489)   10. Wait(1)
11-16. 按主叫号码分流（13822221111 → 02022221112-ivrlogin）
17. Goto(N00000000489-10220-blacklist|${FROM_CID}|1)
```

### 5.2 外呼（坐席打出）

```
坐席话机/软电话（SIP 分机，context=N00000000489）
   → 分机 context 的 _X. → AGI: AgiFormatDialoutNumber（**加前缀 9**）
   → predialout / dialout → 选外线 → gateway(5072)
   → gateway 按 trunk 路由 → 落地运营商
```
⚠️ **加 9 前缀是本系统最反直觉的一条规则**：外呼号码被加 9 后再匹配路由，
路由无匹配时会落到 `MusicOnHold()`（表现为"打通了但没声音"）。详见 09 章。

### 5.3 坐席签入/签出

坐席可用**话机拨特定号码**完成签入签出（不依赖 Web）：
```
context sip-login   : Agi(agisiplogin?pbx=${HOST})      → 成功放 sound/succeed
context sip-logout  : Agi(agisiplogout?pbx=${HOST})
context sip-bind    : Agi(agibindexten?pbx=...&exten=...)  // 话机上绑定工号
context sip-query   : Agi(agibindquery?pbx=${HOST})
```
坐席状态（空闲/忙碌/小休等）通过 `cc.manager_ivr_phonebar_config`（1,133 条，租户自定义状态项）配置，
状态变更日志供"座席状态日志"菜单查询。

### 5.4 计费与运营

- 租户余额：`bill.platform_account.balance`（**单位疑似"分"或"内部计价单位"**，样例 100100000）。
- 计费对象：服务号月租（`platform_serviceNum.monthRent`，样例 500000）、坐席许可（`platform_licence`，含 `licenceType`/`num`/`beginDate`/`endDate`/`channelCount`）、通话消费（`bill_call_consume`）、短信（`bill_sms_channel`）。
- 对账/巡检数据：`bill.db_master_log`（**602,964 条**，按库按天记录 Mongo 各库容量）、`db_master_data_check_log`（21,515）。
