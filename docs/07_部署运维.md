## 二、启停方式（实测）

### 2.1 Node 服务

```bash
cd /opt1/cc-server-in-gddx && setsid nohup /opt/node/bin/node startup.js > /tmp/ccin.log 2>&1 < /dev/null &
cd /opt1/cc-server-out-gddx && setsid nohup /opt/node/bin/node startup.js > /tmp/ccout.log 2>&1 < /dev/null &
```
（ps 里能看到就是这么起的：`bash -c cd ... && setsid nohup ...`）

⚠️ **踩过的坑**：
- 用 `pgrep -f` 匹配自身会把自己杀掉 → 用精确 PID 文件（`node-server.pid`）。
- 直接 `ssh host 'node startup.js'` 会因会话不退出而超时 → 必须 `setsid nohup ... &` 再异步验证端口。

### 2.2 Java 服务

```bash
cd /opt1/cc-java-in-gddx && ./cc-java.sh start      # 或
java -server -Xloggc:/opt1/cc-java-in/log/gc.log -jar cc-java-in.jar /opt1/cc-java-in-gddx
```
配置改完**必须重启**（启动时一次性加载）。

### 2.3 Asterisk

```bash
# 启动单个实例（159 rc.local 的做法）
mkdir -p /dev/shm/astdb /dev/shm/monitor<实例名> /var/run/asterisk/<实例名> /var/spool/asterisk/<实例名>
touch /dev/shm/astdb/astdb<实例名>
/usr/sbin/asterisk -g -C /etc/asterisk/<实例名>/asterisk.conf

# 日常操作（★ 必须带 -C）
asterisk -C /etc/asterisk/gz.ydx.159.0/asterisk.conf -rx 'sip show peers'
asterisk -C /etc/asterisk/gz.ydx.159.0/asterisk.conf -rx 'dialplan reload'
asterisk -C /etc/asterisk/gateway/asterisk.conf -rx 'sip show registry'
```

## 三、开机自启现状（**重大风险**）

| 机 | 自启情况 | 证据 |
|---|---|---|
| **156** | **完全没有** —— rc.local 只有 `touch /var/lock/subsys/local`；chkconfig 里 asterisk 为 off | 所有 Node/Java 服务都是手动 `setsid nohup` 起的，重启即全部丢失 |
| 157 | rc.local 只有两行：nginx、clpms | yy-server 等是手动起的 |
| 159 | **完整** rc.local：`ulimit -n 65535`、nrpe、逐实例启动 10 个 Asterisk | 唯一"重启能自愈"的机器 |

`crontab -l` 在三台上**均为空**（/etc/cron.d 只有 0hourly / raid-check / sysstat）。
`ass_monitor.sh` 的 cron 全被注释（日志停更于 2023-06-13）。
`asteriskGuard` 只告警不重启（日志里 restart/down 零命中）。

**每天 04:00** 有 `gateway_restart.sh` 硬重启 gateway（计划内中断）。

## 五、日志位置

| 服务 | 日志 |
|---|---|
| Node 服务 | `<服务目录>/logs/`（log4js.json 配置）+ 启动时重定向的 `/tmp/ccin.log`、`/tmp/ccout.log` |
| Java 服务 | `<服务目录>/logs/` 或 `log/`；GC 日志 `-Xloggc:/opt1/cc-java-in/log/gc.log` |
| Asterisk | `/var/log/asterisk/<实例名>/` |
| nginx | `/usr/local/nginx/logs/`、`/opt/nginx/logs/` |
| Mongo/Redis/MySQL | 各默认位置 |

## 六、备份要点

- **必须备份**：MongoDB（`cc` + `bill` + `report`）、`/etc/asterisk/`（**含租户 .ael/.conf，页面改动最终都在这里**）、录音目录 `/var/spool/asterisk/<实例>/monitor`、各服务 `serverConfig.json` / `server.conf`。
- **可丢弃重建**：ES（3 个索引共约 90KB）、Redis（AOF 0 字节，纯缓存）。
- 现状是**人工 `tar.gz`**（156 上 `/opt1` 5.8G 大半是备份），**没有自动化备份**。
- 156 磁盘已 96%（剩 1.3G），随时可能写满 —— 优先清理备份包。

## 八、运维常见操作

| 场景 | 操作 |
|---|---|
| 改运营跳转地址 | 改 157 `/opt/yy-server-gddx/serverConfig.json` 的 `ccInUrl`/`ccOutUrl`/`ccInRedirect`/`ccOutRedirect`/`ucenterUrl` → **重启 yy-server** |
| 改 IVR | 在云客服管理后台改 → ass 写回 `/etc/asterisk/accounts/<租户>/*.ael` 并 reload |
| 加坐席 | 管理后台建坐席（工号+密码）→ 分配 SIP 分机 → 写 `users.conf` + `sip.conf` + Mongo |
| 改 RTP 范围 | `rtp.conf` 的 `rtpstart/rtpend` → reload（**当前只有 6 个端口，建议改 10000-20000**） |
| 软电话连不上 | 检查是否用了 `ExtenType=gateway` 的分机（只支持 G.729）→ 换成 `sip` 类型且带 alaw 的 |
| 156 重启后服务全没了 | 手动按 2.1 逐个拉起（**当前没有自启脚本，建议优先补上**） |
