## 三、重复 / 重叠副本（已核实）

| 模块 | 重复位置 | 证据 |
|---|---|---|
| **cc-ass (ASS 源码)** | `容联/cc-ass.zip` 与 `!云呼资料整理/.../code/cc-ass.zip` | 字节数完全相同（95,873,080 B）—精确重复 |
| **cc (云客服源码)** | `cc/cc.zip` 与 `!云呼资料整理/.../code/cc.zip` | 字节数完全相同（141,726,449 B）—精确重复 |
| **fss_gateway** | `容联/源码/fss_gateway`（超集，含 `fss-gateway.tar.gz` 101MB） vs `源码/fss_gateway`（子集，仅 per-jar `.src.zip`） | 同一源码的两份，后者是前者的子集 |
| **ASS 三种形态** | `cc-ass.zip`(95MB) / `ass_156.tar.gz`(120MB) / `ass_32.tar.gz`(60MB) | 疑似同一 ASS 代码的不同快照/压缩方式 |
| **restApi** | `源码/restApi`(目录) / `源码/restApi.rar` / `源码/restApi_node.tar.gz` / `!云呼资料整理/.../code/restApi.zip` | 多版本/多形态共存 |
| **「云呼资料整理」整体** | 其 `code/*.zip` 均为 `容联/源码` + `cc/` 的导出镜像 | 即该文件夹本身就是本系统在 `容联/`、`cc/`、`源码/` 上的**精选重复副本** |
| **自建 vs 云客服/云电销** | `容联/源码/自建/` 内含 `cc-server-in/out`、`cc-client-vue`、`yy-server`——与 `云客服/`、`云电销/` 同名模块 | 同一模块的两套打包（"官方" 与 "自建"） |

**重复结论**：核心源码（`云客服`/`云电销`/`fss_gateway`/`pbx`/`ASS`）在 `容联/源码` 有一份权威树；`!云呼资料整理` 与 `cc/` 是同一树的打包/部署镜像（其中 `cc-ass.zip`、`cc.zip` 为**逐字节相同**的精确副本）；`源码/` 与根目录 `ass_*` 则是零散的二次副本/子集。

### 与「!云呼资料整理」的对照
`!云呼资料整理/呼叫中心` 是该系统的**文档 + 数据库备份 + 源码包 + 运行环境备份**交付集；其 `code/*.zip` 正是 `容联/源码` 与 `cc/` 中对应模块的**导出副本**（其中 `cc-ass.zip`、`cc.zip` 逐字节一致）。也就是说，`容联/`、`cc/`、`源码/` 是源头，而 `!云呼资料整理` 是整理后的"发行镜像"。

## 五、风险提示

1. **敏感信息散布**：`容联/156` 含测试环境 `asterisk`/`gd.zj.1.0` 真实配置与账号目录；`cc-dbtemp`、`云呼资料整理/云呼数据库备份` 含真实 MongoDB/MySQL 业务数据 dump；多处遗留 MongoDB 口令 `7moorcom`、公网 IP、微信/短信接口密钥。
2. **多处精确重复**：`cc-ass.zip`、`cc.zip` 在两份位置逐字节相同；Ass/fss_gateway/restApi 存在多份不同形态副本——整理时建议保留 `容联/源码` 权威树 + `cc/` 部署包，其余作为冗余备份隔离存放，避免误改。
3. **授权**：原始知识产权归**平台原厂**；本目录为第三方整理/转售的交付物，使用前须确认授权合法性。
4. **体量警告**：`容联/源码/自建` 含大量 `node_modules`（约 23 万文件），全文检索易超时；分析时请针对具体子模块（如 `cc-java-in`、`pbx`、`fss_gateway`）缩小范围。

## 六、一句话总结

> `容联/源码` 是本系统（本系统）的**权威源码树**，`cc/` 是其**部署包**，`源码/` 与 `ass_*`、`!云呼资料整理` 是**零散/精确重复副本**；FreeSWITCH/Kamailio/MRCP/Asterisk/Nginx 为**上游依赖**而非系统自有代码。架构为「Asterisk+自研 ASS+FSS 网关」通信层 + 「Java/Node 微服务」业务层 + 「MongoDB/Redis/Consul/Nginx」数据治理层的三层体系。
