## 一、通话无声

### 根因：用错了号码类型 + G.729 编码不匹配

你的通话记录（`app.callSheet.queryCallSheet`）：

```json
CALL_NO: "02022222222"      STATUS: "leak"        CALL_TIME_LENGTH: 0
PBX: "gz.ydx.159.0"         分机: 20008671
DISPOSAL_AGENT: "f20f3bf0-13bf-11ee-aaf3-9d0b35a86868"
```

按 `DISPOSAL_AGENT` 反查 159 的 `accounts/N00000000489/conf/users.conf`：

```ini
[8030]
id=f20f3bf0-13bf-11ee-aaf3-9d0b35a86868
Password=1234Qwer
Local=13822221111
CallerIDNum=02022222222          ← 就是你拨的号码
OwnSipNums=sip:20008660, gateway:20008671, Local:20008661
```

坐席 8030 有三个号码，你选了 **`gateway:20008671`**（网关分机）：

```ini
[20008671]                       ← 你现在注册的
disallow=all
allow=g729                       ← 只允许 G.729
ExtenType=gateway
Codecs : 0x100 (g729)
```

而 MicroSIP 的 `audioCodecs=PCMA/8000/1 PCMU/8000/1`，**没有 G.729**（PJSIP 官方不带）。

Asterisk 日志实锤：

```
[Sep 14 00:17:23] NOTICE[3437] chan_sip.c: No compatible codecs, not accepting this offer!
```

**注册能成功，但媒体协商失败 → 接通了没有声音。** （记录里 `CALL_TIME_LENGTH=0`、`STATUS=leak` 说明其实也没真正接通。）

### 修复：改用 sip 类型分机 20008660

```ini
[20008660]                       ← 坐席话机该用这个
disallow=all
allow=alaw / g729 / gsm          ← 有 alaw，MicroSIP 支持
secret=gmwnrzrr
ExtenType=sip
Codecs : 0x10a (gsm|alaw|g729)
```

MicroSIP 账号设置：

| 项 | 值 |
|---|---|
| SIP Server / Domain | `192.168.1.159:6060`（**159，不是 156**） |
| 用户名 / 认证名 | `20008660` |
| 密码 | `gmwnrzrr` |
| 编码 | 勾选 **PCMA**（alaw） |

已实测：`401 Unauthorized → 200 OK`（测完已发 `Expires:0` 释放）。

> 如果你切回 156 的租户 N00000000488（坐席 8025），对应话机是 `20008647 / bg7ykraf`，同样是 sip 类型。

## 二、云客服提示"服务不可用"

### 根因：配置里指向了不存在的 156:13000

`/opt1/cc-server-in-gddx/serverConfig.json`：

```json
"yyBillUrl" : "http://192.168.1.156:13000/public",      ← 计费服务
"ip_url"    : "http://192.168.1.156:13000/openService"  ← IP 归属地
```

156 上 **13000 端口没有任何监听**（netstat 确认），yy-server 实际在 **157:3000**。

日志里持续报错：

```
[00:20:03] request url3 :[http://192.168.1.156:13000/openService?action=locateIP&ip=192.168.1.1]
[00:20:03] [WARN] request - url3 request error:[connect ECONNREFUSED]
[00:20:03] [ERROR] app - locate ip failError: connect ECONNREFUSED
```

（该错误从 2023-12 就存在。）

而前端 `cc-client-in-gddx/javascripts/config/callConfig.js` / `handler/callConfig.js`：

```js
errorMessage: {
    'serviceNo_401': '服务号已被占用或不存在',
    'serviceNo_500': '检查服务号失败，计费服务不可用'   ← 你看到的提示
}
```

"设置 / 高级功能 / 通话配置"这几个页面都会校验计费侧数据，调到 13000 就炸。

### 已修复

```
yyBillUrl : http://192.168.1.156:13000/public       → http://192.168.1.157:3000/public
ip_url    : http://192.168.1.156:13000/openService  → http://192.168.1.157:3000/openService
```

- 备份：`serverConfig.json.bak.20260914`
- 重启 cc-server-in，已重新监听 3000（`Express server listening on port 3000`，PID 125253）

### 残留一个小问题（不影响通话）

`locateIP` 用 `?action=` 传参，但 yy-server 的 `/openService`（`routes/index.js`）期望 `command=`，否则 `utils.send403`：

```js
var command = { name: data.command, data: data.data };
...
} else { utils.send403(res, uuid); }
```

所以直连 157:3000 会返回 `403 Forbidden!`。影响：通话记录里的**归属地（LOCATION）字段为空**，不影响呼叫。
（顺带一提：`externhost=www.pbx159.com` 在 159 上也解析不到，NAT 场景外可能有影响。）

## 四、排查中踩到的坑

1. **别只看一台机**：156 和 159 都跑 Asterisk 且**都用 6060 端口**，凭 IP 猜会认错 PBX。要以通话记录里的 `PBX` 字段 + `DISPOSAL_AGENT` 反查为准。
2. **确定坐席用哪个分机的权威方法**：`accounts/<租户>/conf/users.conf` 里按 `id=` 匹配 `DISPOSAL_AGENT`，再读 `OwnSipNums`。
3. **改 `serverConfig.json` 必须重启服务**——配置是启动时一次性加载的（yy-server、cc-server-in 都一样）。
4. **杀进程别用 `pgrep -f`**（会匹配到执行它的 shell 自己，导致自杀）；用 `ps -eo pid,args | awk '/路径/ && !/awk/ {print $1}'`。
5. 启动 detached 进程要用 `bash -c '... setsid nohup ... > /tmp/x.log 2>&1 < /dev/null & echo OK'`，否则 SSH 通道不返回会超时（但进程其实起来了，需另开命令验证）。
