## 一、填 `192.168.3.30:6060` 是绕路（虽然当前侥幸能通）

本机路由表关键两条：

```
192.168.1.0/24  -> ifidx 9   (VMware Network Adapter VMnet8，主机地址 192.168.1.1)
192.168.3.0/24  -> ifidx 12  (WLAN，主机地址 192.168.3.30)
```

- 156 就是**本机 VMware 里的虚机**（你说得对），主机在 VMnet8 上的地址是 `192.168.1.1`，和 156 同网段直连，**根本不需要任何转发**。
- 你填 `192.168.3.30:6060` 后，包要先送到本机 WLAN 地址、再经 VMware 一层转发才到 156，源 IP 变成 `192.168.3.30`——这个地址**不在 Asterisk 的 `localnet` 里**，会被当成外部 NAT 客户端处理。

Asterisk 侧配置（`/etc/asterisk/gd.zj.1.0/sip.conf`）：

```
externip = 192.168.1.156
localnet = 192.168.1.0/255.255.255.0
nat      = yes (Always)
bindport = 6060
realm    = cc-ali-0
```

后果在日志里很清楚（ini 被修改的那一刻）：

```
[Sep 14 00:02:51] Peer '20008649' is now Reachable.   (3ms / 2000ms)
[Sep 14 00:03:06] Peer '20008649' is now UNREACHABLE! Last qualify: 3
```

**注册成功 15 秒后就被判死**——正是 NAT 路径不稳定导致 qualify 探测丢包。

> 当前 Asterisk 记录的 Contact 是 `192.168.1.1:59597`，说明最终还是走了 VMnet8 直连，所以暂时是 OK 的。

**正确填法：`192.168.1.156:6060`**

## 二、编码不匹配——注册成功也打不了电话

| 侧 | 配置 | 值 |
|---|---|---|
| Asterisk 分机 20008649 | `disallow=all` / `allow=g729` | **只有 G.729** |
| 你的 MicroSIP | `audioCodecs=PCMA/8000/1 PCMU/8000/1` | **只有 G.711 a/μ** |

```
Codecs       : 0x100 (g729)
Codec Order  : (g729:20)
```

MicroSIP（PJSIP）**官方不带 G.729**——它是专利编解码，需要单独授权编译。

结果：**注册没问题，但一呼叫就编码协商失败**（488 / 接通无声）。这才是"连不上"最实际的体感。

## 三、最根本的原因：20008649 不是坐席话机分机

租户 `N00000000488` 的 `conf/users.conf`：

```ini
[8025]                         ← 8025 是【坐席工号】，不是端口
id=ecd9a0f0-ebef-11ed-9af2-b739812edbf4
Password=1234Qwer
Exten=8025
Local=13824424556              ← 绑定手机号
OwnSipNums=sip:20008647,gateway:20008649,Local:20008648
```

对应 `sip.conf` 里的三个号码，角色完全不同：

| 号码 | ExtenType | 编码 | 密码 | 用途 |
|---|---|---|---|---|
| **20008647** | `sip` | gsm, **alaw**, g729 | `bg7ykraf` | **坐席 SIP 话机**（MicroSIP 该用这个） |
| 20008649 | `gateway` | **仅 g729** | `snl61rup` | 网关分机，出局中继用 |
| 20008648 | `Local` | — | — | 绑定手机 13824424556，host=10.0.0.156.156:5072 |

你表格那一行的真实含义是：

```
20008649 | snl61rup | g729 | gd.zj.1 | 8025 | 未注册 | 192.168.1.156:6060
  号码   |   密码   | 编码 |   域    | 坐席 | 状态   | SIP 服务器地址
```

**云客服页面显示的"未注册"，盯的很可能是坐席的 sip 分机 20008647，而不是 gateway 分机 20008649。**

## 四、推荐配置（改完就能用）

MicroSIP → 账号设置：

| 项 | 值 |
|---|---|
| SIP Server / Domain | `192.168.1.156:6060` |
| 用户名（username） | `20008647` |
| 认证名（authID） | `20008647` |
| 密码 | `bg7ykraf` |
| 传输 | UDP |
| 编码 | 勾选 **PCMA**（alaw），去掉不用的 |

已实测验证（测完立即发 `Expires:0` 注销，不占用分机）：

```
20008647 / bg7ykraf  →  401 Unauthorized  →  200 OK  →  dereg 200 OK
20008649 / snl61rup  →  401 Unauthorized  →  200 OK  →  dereg 200 OK
```

如果业务上**必须**用 20008649，那得解决 G.729：换支持 G.729 的软电话（如 Zoiper 付费版 / eyeBeam / Linphone 带 g729 插件），或让 Asterisk 侧给这个分机加 `allow=alaw`。

## 七、排查中踩到的坑

1. **UDP 探测脚本不要一收到包就 `sock.close()`**——Asterisk 会先回 `100 Trying` 再回 `401/200`，提前关 socket 会误判成"服务器无响应"（我第一版就踩了，误以为 156:6060 不通）。
2. **`pgrep -f "node app.js"` 会匹配到执行它的 shell 自己**，导致自杀式 kill（上一轮排查已踩过）。
3. **ini 修改时间 vs 进程启动时间**：MicroSIP 的 `MicroSIP.ini` 是 UTF-16LE（`FF FE` 开头），且 GUI 改配置后需确认是否重注册；本次 ini 写于 00:02:51、进程启动于 23:20:23。
4. **MicroSIP 的密码在 ini 里是加密的**（`password=140f4b63...`，20 字节 hex），无法直接核对明文，只能靠服务端返回 `200 OK` 反证密码正确。
