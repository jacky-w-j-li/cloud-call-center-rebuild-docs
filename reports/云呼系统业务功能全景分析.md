## 2. 呼入业务：服务号 → IVR → ACD → 坐席

### 2.1 服务号（接入号）

服务号是呼入的入口，本质是 **一个 Asterisk context**（不是普通号码）。

```ini
; accounts/N00000000489/conf/service_no.conf
[02022221112]
Type= normal
DisplayName= serviceno-02022221112
ToPeer= 10220          ; 指向流程首节点（此处为黑名单节点）
```

```ael
context 02022221112 {
	_X. => {
		FROM_CID=${CALLERID(num)};          ; 主叫
		FROM_DID=${EXTEN};                  ; 被叫（服务号）
		ACCOUNT=N00000000489;
		Agi(agi://127.0.0.1:7891/gaicalllimit?...&servicepeer=02022221112);  ; 并发限制
		Answer;
		if("${FROM_CID}" = "13822221111") goto 02022221112-ivrlogin,s,1;     ; 坐席号码识别
		goto N00000000489-10220-blacklist,${FROM_CID},1;
	}
}
```

关键能力：
- **并发限流**（`gaicalllimit` AGI，按服务号限并发）
- **主叫识别分流**：坐席用自己的手机号打进来 → 进入 IVR 签入菜单，普通客户 → 走业务流程
- **服务号类型**：`Type=normal`，另有 `light-serviceno`（轻量型，488/490/491 租户使用）

### 2.2 IVR 流程编排：28 类节点

这是系统最强的部分——**可视化拖拽的 IVR 流程引擎**，编排结果直接编译为 Asterisk AEL。每个租户目录下有 28 个 `.ael` 文件，每类对应一种节点：

| 节点类型 | 文件 | 业务作用 | 配置证据 |
|---|---|---|---|
| **语音公告** | `announcement.ael` | 播放上传的录音文件 | `Playback(sound/upload_30c9604713...)` |
| **文本转语音（TTS）** | `text_announcement.ael` | 文字转语音播放 | `Agi(agi://127.0.0.1:7891/agittszh)` → 阿里 TTS |
| **时间条件** | `time_condition.ael` | 按星期/时段分流 | `Times=*,mon&tue&wed&thu&fri&sat&sun,*,*`、`MatchedPeer=10218` |
| **日期节点** | `date_node.ael` | 按日期区间分流 | — |
| **黑名单** | `blacklist.ael` | 拦截骚扰号码，匹配/不匹配双分支 | `MatchedPeer=0`（挂断）、`UnmatchedPeer=10219` |
| **红名单** | `redlist.conf` | VIP 免拦截直通 | `List=0201000,1000` |
| **按键菜单** | `ivr.ael` / `ivr_menu.ael` | 多层按键导航 | `IvrKey=1@10015117,2@c6425670-...`，`Timeout=10`、`RetryTime=3` |
| **信息采集** | `validate.ael` | 采集客户按键输入（会员号/订单号等） | `Min=0`、`EndLength=1`、`EndType=0`、`ReturnKey=*`、`WaitTime=20` |
| **动态路由** | `dynamicroute.ael` | 按变量值智能分流 | `RouteRules=0&10199&key:0:0404`、`0&10239&asr结果:0:好` |
| **变量赋值** | `assignment.ael` | 流程内设置变量 | `SetVar=key=180` |
| **URL 接口节点** | `callurl.ael` | 调用外部 HTTP 接口并取返回值 | `Url=http://.../callMemory?flag=1&callNo=FROM_CID&accountId=ACCOUNT&callMemory=2`（主叫记忆） |
| **自定义拨号** | `extension_peer.ael` | 内嵌任意 AEL 代码，无限扩展 | `DialPlan="context ... { goto N00000000489-dialin,${key},1; }"` |
| **技能组排队** | `queue.ael` | 进入 ACD 队列 | `Queue(10015123,t,,,20)` + 空队列/等待/挂断三种转移 |
| **满意度评价** | `satisfaction.ael` | 通话后按键评分 | 重录 3 次、有效/无效/结束/超时各有独立语音 |
| **问卷调查** | `investigate.ael` | 多题按键调查 | `RETRY_TIME > 3` 退出 |
| **语音留言** | `voicemail.ael` | 客户留言并录音 | `Record(${RECORD_FILENAME}.wav)`，`*` 重录、`1` 确认 |
| **ASR 语音识别** | `asr.ael` | 识别客户说话内容 | `IsRobotHandle=true`、`EndRobotKey=再见`、`SilenceTime=2` |
| **工号直拨** | `dialjobnum.ael` | 客户输入工号直呼坐席 | 含 `-agentbusy`、`-logoff` 分支 |
| **超级直拨** | `superDialJobNum.ael` | 增强版工号直拨 | — |
| **呼入路由** | `callroute.ael` | 号码路由分发 | `context N00000000489-route` |
| **双向回呼** | `twowaycall.ael` | 平台先后呼叫双方再桥接 | 已 include（489 租户未配置内容） |
| **网页回呼** | `webcall.ael` | 网页上留号码，系统回呼 | 已 include；`interAPI.account_webcall_serviceno` 提供开放接口 |
| **会议室** | `room.ael` | 多方会议室 | — |
| **分机拨打** | `dialexten.ael` | 内部分机互拨 | — |
| **外呼/转外线** | `dialout.ael` | `predialout` / `dialout` / `transferout` | — |
| **服务号入口** | `serviceno.ael` | 呼入总入口 + IVR 签入签出 | — |
| **MD5 加密** | `encrypt_md5.ael` | 流程内加密运算 | — |
| **等待音乐** | `moh.conf` | 自定义 MOH | 租户目录有 `moh/` 子目录 |

实测节点实例（489 租户）：语音公告 4 个、文本语音 5 个、时间条件 2 个、黑名单 2 组、按键菜单 2 个、动态路由 3 个、自定义拨号 3 个、技能组 2 个、满意度 1 个、信息采集 1 个、ASR 1 个、留言 1 个。

> 支持**嵌套与跳转**：`goto` 到任意节点，配合动态路由可实现「客户说'好' → 走 A 分支，否则走 B 分支」这类语义路由。

### 2.3 技能组与排队（ACD）

`cc.manager_ivr_skillgroup` 字段完整暴露了 ACD 能力：

```
Strategy（分配策略）、SayExten（播报工号）、JoinEmpty（空队是否允许加入）、
WaitTime、Timeout、
ToPeerWhenQueueEmpty / ToPeerWhenWait / ToPeerWhenWaitTimeout / ToPeerWhenHanguped（四种溢出策略）、
AssignMembers（组成员）、BussinessTypeId（关联业务类型）
```

`queue.ael` 的运行时逻辑：
```ael
if (${QUEUE_MEMBER_COUNT(10015123)} == 0) goto ...-queue-empty-transfer;   ; 无坐席在线
Set(RECFILENAME=...); Playback(sound/queue);
Queue(10015123,t,,,20);       ; t=被叫可转移，20 秒超时
goto agentbusy,s,1;
h => goto ...-queue-hangup-transfer;   ; 客户挂断也走转移
```

**四种溢出场景都有独立出口**：队列空、等待超时、客户挂断、坐席忙。

另有 `mail_queue.conf` 支持**邮件队列**（`strategy=rrmemory`、`Members` 多成员、`timeout=40`）——邮件也能像电话一样排队分配。

### 2.4 坐席应答方式

`conf/users.conf` 定义了坐席的接听方式：

```ini
[8030]
Password=1234Qwer
Exten=8030                              ; 工号
Local=13822221111                        ; 绑定手机
OwnSipNums=sip:20008660,gateway:20008671,Local:20008661
AutoBusyTime=0                           ; 话后自动置忙秒数（话后处理）
CallerIDNum=02022221112                  ; 外呼显号（可按坐席差异化）
UCExtenType=sip
DialoutType=
Version=enterprise
```

三种接听终端：**SIP 软/硬话机**（`sip:`）、**网关分机**（`gateway:`，仅 G.729，出局用）、**手机**（`Local:`，绑手机号转呼）。

### 2.5 IVR 签入 / 签出（话机即坐席）

坐席用手机打进服务号，系统识别主叫后进入签入菜单：

```ael
context 02022221112-ivrlogin {
	s  => { BackGround(sound/ivrlogin); WaitExten(20); }
	1  => goto ...-jobnumconfirm;     ; 签入
	2  => goto ...-jobnumconfirmout;  ; 签出
	3  => goto 02022221112,loop;      ; 返回
	4  => goto ivr-flow-checking;     ; 流程自检
	t  => Playback(sound/timeout);    ; 超时
	i  => BackGround(sound/incorrect);; 无效按键
}
```
工号最多 10 位，`#` 结束，签入结果经 `AgiProcessIvrLogin` 写库，返回 1/500/501 分别播放成功/超限/工号错误。

**业务价值**：没有电脑的场景（外勤、门店）用手机就能签入接电话。

## 3. 呼出业务：云电销

### 3.1 坐席手工外呼
- 坐席端点击拨号 / 软电话条拨号
- **显号控制**：`CallerIDNum=02022222222`（`dialout.ael` 中强制设置），可按坐席配置不同外显号码
- **出局线路选择**：`dialout_line.conf` 按前缀选线路（`[096]` 段），支持多主叫号码轮选（`MultiDidNum`/`MultiDidStrategy=order`/`MultiDidEnable`）

### 3.2 号码预处理
`predialout` 做了完整的号码规整：
```ael
_020X.            => goto dialout,${EXTEN:3},1;          ; 去掉本地长途前缀
_01[3458]XXXXXXXXX => Agi(AgiIsLocalNumber); 本地则去首位 0
_1[3458]XXXXXXXXX  => 非本地则补 0                        ; 手机号补 0
_110X.            => Hangup;                             ; 禁止拨打 110 等特服
```
外加 `AgiIsOutboundBlackList` 出局黑名单校验 + `nums.conf` 手工黑名单（`Num=15476111425,...`）。

## 14. 总结：能干什么

按使用场景归纳：

**场景 A — 企业热线/客服中心**
申请服务号 → 配 IVR（欢迎语/按键菜单/工作时间/黑名单/满意度）→ 配技能组排队 → 坐席用电脑软电话或手机接 → 通话全程录音 → 事后质检评分 → 出话务报表。全链条齐备。

**场景 B — 电销团队**
导入号码 → 建外呼任务/批量外呼 → 坐席点击外呼（可按坐席配外显号码）→ 通话录音 → 客户跟进状态审批 → 外呼报表 + 座席工作量报表。

**场景 C — 全渠道客服**
网页 IM、微信、邮件、短信统一接入 → 统一会话分配 → 转工单 → 关联客户档案 → 知识库支撑 → 机器人前置应答（Sobot）→ 人工接管。

**场景 D — 平台运营方（你们）**
多租户开通 → 按坐席数/服务号数/并发数卖许可 → 配置资费（通话费、转接费、月租、最低消费、赠送分钟、折扣、国际费率）→ 充值扣费 → 出运营/代理/销售报表 → CDR 推 FTP 给客户。

**一句话**：它的功能边界覆盖了 Genesys Cloud / 天润融通 / 平台原厂这一类中端云呼叫中心的**绝大部分能力清单**，短板不在"有没有"，而在"配不配得对、跑不跑得稳"——尤其是外呼最后一跳的 dialplan 不匹配、租户集中在单实例、以及 156 的资源告警，这三点是当前真正的卡点。
